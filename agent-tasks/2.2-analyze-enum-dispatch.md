# Task 2.2. Analyze the enum dispatch results

Analyze existing measurements from
[Task 2.1](2.1-implement-enum-dispatch.md). Use the repository's
[project structure](../agent-rules/project-structure.md),
[report format](../agent-rules/report.md), and
[target rules](../agent-rules/targets.md). Follow the shared
[benchmark analysis rules](../agent-rules/analysis.md).

## Inputs

- Read `reports/enum-dispatch-test/*-report.csv` and the associated run and
  diagnostic logs. If the caller specifies another input directory, use its
  reports and logs.
- Use logs to verify the effective size, seed, repeat count, value, and
  checksum validation. Task 2.1 allows language-specific RNGs, so a shared
  seed can produce different operation sequences. Compare those results as
  equivalent workloads with the same input distribution.

## Analysis

- Treat one benchmark operation as one complete call to `run`.
  Use `time_per_op` in `ns/op` as the primary metric. If reporting time per
  tag-dispatch decision, divide by `size * repeats` and label it separately.
- Report what the workload measures, including traversal, tag loading and
  branching, arithmetic, and checksum accumulation. Attribute differences to
  isolated tag-dispatch overhead only if a matched control is available.
- Compare the results with Task 1.2 only when the host, workload settings,
  build configuration, execution mode, and resource controls match. Without
  a controlled comparison, note that differences can also come from data
  representation, layout, and generated code.

## Done when

- The workload analysis identifies the input runs, explains the method,
  presents comparable results, and states what the measurements support and
  where evidence is missing.
- Original CSVs and logs are preserved. This task analyzes existing results.
