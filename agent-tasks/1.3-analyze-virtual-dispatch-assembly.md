# Task 1.3. Analyze virtual dispatch assembly

Inspect the generated code for [Task 1.1](1.1-implement-virtual-dispatch.md)
across the [benchmark targets](../agent-rules/targets.md). Follow the
[assembly analysis rules](../agent-rules/assembly-analysis.md).

## Work to perform

- Use a representative Task 1.1 case. Match the recorded workload settings
  and build configuration when a timing run is available. Reuse existing
  artifacts or collect evidence in a separate diagnostic run. Keep JIT
  diagnostic flags out of every performance measurement run, including
  warmup. Use only clean-run timings for comparisons with Task 1.2.
- Locate the hot loop in `run` or the optimized caller that contains it.
  For each target, determine how the call to `Operation.process` is
  implemented. Look for indirect dispatch, direct calls, type guards and
  fallbacks, or inlined arithmetic. For C, inspect the equivalent function
  pointer call. For CPython, identify the method lookup and call in bytecode.
- Inspect how the code loads the receiver and operand, performs addition or
  multiplication, and accumulates the wrapping 32-bit checksum. For JIT
  targets, compare early and optimized versions when both are available.
- Attempt collection for each applicable target. Continue when a toolchain,
  decoder, or usable artifact is unavailable. Identify skipped targets
  and capture failures with their reasons.

## Outputs

- Write the Markdown analysis to `reports/virtual-dispatch-test-assembly.md`.
- Keep raw diagnostic output under `reports/virtual-dispatch-test/assembly/`,
  separated by target and diagnostic run. Keep timing reports separate.
- Include a target comparison table with the evidence type, observed
  dispatch mechanism, tier or build configuration, and capture status.
  Link to the raw files and include short annotated excerpts for the
  findings that matter.

## Done when

Every target is accounted for in the report. Each dispatch conclusion points
to a specific listing or bytecode excerpt. If relating code generation to
Task 1.2 timings, identify the matching configurations and distinguish
observations from explanations that would require a controlled comparison.
