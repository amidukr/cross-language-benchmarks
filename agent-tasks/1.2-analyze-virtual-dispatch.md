# Task 1.2. Analyze the virtual dispatch results

Analyze existing measurements from
[Task 1.1](1.1-implement-virtual-dispatch.md). Use the repository's
[project structure](../agent-rules/project-structure.md),
[report format](../agent-rules/report.md), and
[target rules](../agent-rules/targets.md). Follow the shared
[benchmark analysis rules](../agent-rules/analysis.md).

## Inputs

- Read `reports/virtual-dispatch-test/*-report.csv` and the associated run
  and diagnostic logs. If the caller specifies another input directory,
  use its reports and logs.
- Use logs to verify the effective size, seed, repeat count, value, and
  checksum validation. Task 1.1 allows language-specific RNGs, so a shared
  seed can produce different operation sequences. Compare those results as
  equivalent workloads with the same input distribution.

## Analysis

- Treat one benchmark operation as one complete call to `run`.
  Use `time_per_op` in `ns/op` as the primary metric. If reporting time
  per dispatch, divide by `size * repeats` and label it separately.
- Report what the workload measures, including traversal and arithmetic as
  well as dispatch. Attribute differences to isolated dispatch overhead only
  if a matched control is available.

## Done when

- The workload analysis identifies the input runs, explains the method,
  presents comparable results, and states what the measurements support and
  where evidence is missing.
- Original CSVs and logs are preserved. This task analyzes existing results.
