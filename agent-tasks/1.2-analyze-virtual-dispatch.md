# Task 1.2. Analyze the virtual dispatch results

Analyze existing measurements from
[Task 1.1](1.1-implement-virtual-dispatch.md). Write the analysis to
`reports/virtual-dispatch-test.md`, alongside the workload's report directory.
Use the repository's [report format](../agent-rules/report.md) and
[target rules](../agent-rules/targets.md).

## Inputs

- Read `reports/virtual-dispatch-test/*-report.csv` and the associated run
  and diagnostic logs. If the caller specifies another input directory,
  use its reports and logs. Keep the Markdown output at the path above.
- Record the source filenames and selected run IDs. Validate the CSV
  schema and units. Flag duplicate or incomplete trials, missing targets,
  and any missing provenance that prevents comparison.
- Match workload settings, execution mode, host, and resource controls
  before comparing targets. Keep native and container runs separate.
  Split Docker and Podman runs when the logs identify both. Use logs to
  verify the effective size, seed, repeat count, value, and checksum
  validation. Task 1.1 allows language-specific RNGs, so a shared seed
  can produce different operation sequences. Compare those results as
  equivalent workloads with the same input distribution.

## Analysis

- Treat one benchmark operation as one complete call to `run`.
  Use `time_per_op` in `ns/op` as the primary metric. If reporting time
  per dispatch, divide by `size * repeats` and label it separately.
- Inspect each trial's ordered samples against `elapsed_ms`. Describe
  warmup trends, shifts, and spikes. Use the workload's documented
  stability criterion if available. Otherwise, state a common criterion,
  including window size, tolerance, and minimum sample count, before
  classifying samples. Keep inconclusive samples unclassified and
  report trials that did not demonstrate stability.
- For each comparable group, report a table with target, trial count,
  sample count, median, and spread. Summarize each trial first, then
  compare trial medians so one long trial cannot dominate. Label
  single-trial results and keep warmup, unclassified, steady-state, and
  startup figures separate. Retain slow samples and document exclusions.
- Use diagnostic logs to explain observed transitions where supported.
  Distinguish confirmed JIT activity from plausible explanations. Report
  what the workload measures, including traversal and arithmetic as
  well as dispatch. Attribute differences to isolated dispatch overhead
  only if a matched control is available.

## Done when

- `reports/virtual-dispatch-test.md` identifies the input runs,
  explains the method, presents comparable results, and states what the
  measurements support and where evidence is missing.
- Original CSVs and logs are preserved. This task analyzes existing
  results. If no usable reports are present, state which inputs are
  missing in the Markdown report and leave numerical comparisons empty.
